# 正規表現で足りる？"判定専用"AIモデルを試してみた

読み上げ用の原稿に、うっかり英単語が1つ混ざっていたことはありませんか。

私はこれで、合成音声がそこで不自然に読み上げてしまう事故を何度かやりました。
「日本語の中に英語が混ざっていないか」を判定したいだけなのに、意外と厄介です。
手で確認するのは現実的でなく、正規表現で弾くのが定番だと思います。

最近 OpenRouter に、この手の判定に使えそうな系統のモデルが出ていました。
これなら先ほどの悩みも楽になるのでは、と思って実際に試してみました。
この記事はその記録です。結論から言うと、期待したほどではありませんでした。

## 先に結論

**多くの場面では、正規表現で足ります。**

今回試した「判定専用」のモデルは、指示文の書き方で結果が大きく変わります。
しかし正規表現を明確に上回ることはありませんでした。
無料の汎用チャットモデルでも、ほぼ同じ結果が出ます。

一方で「使う価値がある条件」ははっきりしていました。
その判断材料を、実測値つきで残しておきます。

## こういうものが、出てきました

OpenRouter に、少し変わった系統のモデルが追加されていました。

- respan/span-01-lite、span-01-lite:free
- respan/span-01
- typesafe/jev-router

これらは文章を生成するチャットモデルではなく、
**「ある行動に当てはまるかを確率で返す」**モデルです。

公式のモデルページとドキュメントはこちらです。

- span-01-lite: https://openrouter.ai/respan/span-01-lite
- span-01: https://openrouter.ai/respan/span-01
- jev-router: https://openrouter.ai/typesafe/jev-router
- ドキュメント: https://openrouter.ai/docs/guides/community/jev

ドキュメントによると、自然文で「何を判定したいか」を定義し、
その確率を受け取る使い方をします。
分類器を、学習させずにプロンプトで作れる、という位置づけです。

## どんな悩みに使えそうか

冒頭の悩みは、まさにこの形に当てはまりそうです。
やりたいのは「日本語の原稿に英語が混ざっていないか」の判定です。

従来のやり方は正規表現でした。実際よく動きます。
ただし、静かに壊れる場所があります。

- 英単語が1つだけ、日本語に直接くっついている場合（取りこぼす）
- 逆に、ブランド名や人名、コード片を誤って検知する場合

この「取りこぼし」と「誤検知」を、
自然文で定義できるモデルなら改善できるのでは、と考えました。

## 実際に試してみた（測り方）

思いつきではなく、比較できる形で測りました。
用意したのは2種類のデータです。

1つ目は、境界線ぎりぎりの文を自分で作った合成スイート（23件）。
英語の単語、英語の文、カタカナ語、ブランド名、人名、URL、略語、コード片、
ロール名などを1件ずつ並べています。

2つ目は、実際の日本語ナレーション原稿です（約200件）。
そのうち英字を含むものを全部と、含まないものを一部抜き出しました。

比較したのは3つです。

```
[ 入力: 日本語の原稿 ]
   │
   ├─ 正規表現      決定的・0円・0秒
   ├─ 判定モデル    自然文で定義 → 確率
   └─ 汎用チャット   YES/NO で答えさせる
```

呼び出しはすべて公式のAPI経由で、合計200回あまり。
全リクエストで課金は0円、レート制限にも当たりませんでした。
