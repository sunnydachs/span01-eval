# Track A — 実データでの with/without (2026-09-27)

コーパス: 日本語ナレーション 211件（`*/story.json`）。うちラテン語トークンを含む=22件、
クリーン=189件から決定的に30件をサンプル。合計52件を採点。
実行: 52コール、エラー0、429なし、`cost=0` 全件、各 0.31–1.68s（実測。中央値 0.39s）。

## 判定（gate v4, 閾値0.5）
- クリーン30件の誤検知 0（最大 0.048）
- ラテン語含有22件のうち **21件を検知**（0.529–0.953）
- 唯一の未検知: ラテン語の役割名詞を含む1件（確率 0.025）

## 3手法の比較（ラベル基準で見え方が変わる）

**(a) strict: ラテン語が出たら全て欠陥 — 循環的なので結論に使わない**
```
method TP  FP  FN  TN    P      R      F1
none    0   0  22  30   nan   0.000   nan
regex  22   0   0  30   1.000  1.000  1.000
gate   21   0   1  30   1.000  0.955  0.977
```

**(b) lenient: 実コーパスのキャラクター名を許容**（`--exempt <name>` が必要。
`scripts/rerun_all.sh` は指示文の例 `Kuro` を渡すだけなので、そのままでは (b) は再現しない）
```
method TP  FP  FN  TN    P      R      F1
regex  18   4   0  30   0.818  1.000  0.900
gate   17   4   1  30   0.810  0.944  0.872
```
ここでの FP=4 は「キャラクター名だけがラテン語の4件」。正解基準の定義は `LABELS.md`。

## 重要な注意
1. **strict の比較は循環的**。クリーンの30件は「ラテン語を含まない」と定義して
   抜き出した集合なので、ラテン語検出器なら何でも100%になる。
   このコーパスには「許容される英字」（ブランド名等）がほぼ無く、**弁別力は測れない**。
   → 「regex 22/22 対 gate 21/22」を **正規表現がモデルに勝った証拠として使ってはならない**。
2. **固有名詞の除外は例示駆動で脆い**。指示文に載せた例（この実験では `Kuro`）しか
   除外されない。実コーパスのキャラクター名は指示文に載っていないため全件検知された。
3. 実データの混入はほぼ「隣接 or 空白区切り」型なので、**このコーパスに限れば** 4行の regex で拾える。
   ただし境界ケース（ブランド/URL/人名/略語）では正規表現は誤検知を大量に出す（Track D）。
   同じ正規表現が合成23件では F1 0.522 になる。
4. 結果は単発実行。信頼区間なし。正解ラベルは `LABELS.md` の版に依存する。
